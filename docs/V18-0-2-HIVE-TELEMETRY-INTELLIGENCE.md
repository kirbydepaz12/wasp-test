# WASP v18.0.2 — HIVE Telemetry Intelligence (staging)

Baseline: exact v18.0.1. The update is additive; existing music, R2 bindings, local database state, sessions, playlists, peer origins, metadata credentials and request history are not reset. No live deployment has been performed.

## Docker-first enrichment

1. Back up the repository, database state and music volume mappings. Verify adequate root disk free space before building.
2. Deploy to a test Docker instance first. Confirm the version in the admin sidebar.
3. Open **Admin → Network → Telemetry**. Save a valid MusicBrainz contact (email or URL), enable MusicBrainz and optionally Wikidata fallback. Keep frequently played priority enabled. Last.fm is optional and is not a release-year or artist-origin authority.
4. Press **Scan missing metadata**. Docker performs persistent, bounded background batches independent of the browser. Pause, resume or stop at batch/job boundaries. The scanner rebuilds its work from retained history and library metadata; it does not re-download music. The progress bar is indeterminate while discovering jobs, then shows processed versus currently due jobs. A completed scan pass is not a guarantee every field was verified. Unresolved lookups remain eligible for later retry. Explicit Start after completion scans again; normal scheduled enrichment remains available for incremental follow-up.
5. Enable network sharing and telemetry sharing on Docker (as appropriate for your installation). Ensure the Cloudflare Worker can actually reach the Docker peer using its registered endpoint (a private Tailscale address alone normally cannot be reached from a Worker). Configure appropriate secure connectivity; do not expose the internal scheduler port or scanner secret.
6. On a staging Cloudflare WASP, register Docker as an administrator peer. In **Admin → Network → Telemetry**, enable trusted peer metadata, choose Docker as Preferred metadata peer, disable local scheduled enrichment if you want pull-only operation, and save. Click **Pull metadata from HIVE**. Peer-only pulls are incremental, up to 20 verified factual records per invocation; repeating or scheduling pulls moves the cursor forward. Configure a longer interval if D1 use is a concern. An unreachable peer reports an error; no fallback to remote providers is forced in pull-only mode. Only locally verified MusicBrainz/Wikidata facts are exported by default, no API keys or listening identities; imported facts are not re-exported as local validation. Last.fm sharing is subject to provider terms and off by default.

Cloudflare imports still use D1. Existing saved provider settings are respected; disable previously enabled local enrichment explicitly. Docker still uses provider limits, local disk, CPU and network. Unknown release years are never estimated. Provider 429/503 stops the continuous pass until the retry time; other unresolved fields are rescheduled rather than repeatedly hammered.

## Telemetry accuracy

A listen is confirmed at the existing 10-second playback threshold. A repeat cycle has its own play ID, while failover and transient delivery retries keep the same ID. Counter, recent history and telemetry ledger writes use a single database transaction. Browser retry queue persists in the current tab's session storage (bounded to 100 pending events / 24 hours). Delivery is best effort; closing the tab before retry or a permanent network failure can still lose a listen. Source relay remains best effort, while the listening instance records the confirmed event. The year filter now covers the requested whole year. The visible telemetry dashboard refreshes automatically (Docker 60 seconds, Cloudflare 5 minutes), retains the existing player and current country/decade selection, and has a manual refresh button. Cloudflare refresh may use cached statistics until expiry, to limit D1 reads. Coverage updates when verified facts are stored/imported.

## Request synchronization and transient errors

The reported screenshots show a cross-request promise error and intermittent HTTP 500; there is no Worker stack trace proving that they have the same cause. This release prevents shared pending database initialization/cache promises between requests and retains only resolved values. HIVE request event/state/cursor persistence is transactional; a failed state write cannot advance the cursor. A bounded repair pass replays the existing ledger to restore missing request state, preserving newer completed/cancelled states and local dismissals. Admin queue retries a transient server error once and retains previously loaded rows if it still fails. Watch origin request completion, peer feed cursors, and the Worker error log during a three-server staging test.

## Validation / rollback

Run `npm test` under Node 22 or newer. Chromium UI scripts in `tests/` use mocked APIs and local browser media; they require Python Playwright and Chromium. Actual Docker image builds, provider connectivity and the Cloudflare Worker runtime were not validated here. Stage first; capture Worker logs on recurrence (do not share secrets). Do not delete persistent volumes or reset D1. For rollback restore the v18.0.1 source and rebuild against the same volumes/bindings after backup. Additive metadata/request settings may remain; a stopped scanner will not execute on the older source. Restore data snapshots only if a verified data fault warrants it.
