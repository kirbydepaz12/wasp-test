# WASP v17.0.5 — HIVE Metadata Intelligence & Resource Optimization

Staging release from the exact v17.0.4 baseline. The persistent player, stream routing, audio objects, accounts, playlist ownership, telemetry event IDs, peer cursors, Spotify completion rules and existing configuration are retained. HIVE Smart Routing / adaptive load balancing / playback failover remain planned for v18.

## Set up metadata enrichment

Open **Admin → Network → Telemetry** (`/admin#network/telemetry`).

1. Choose **MusicBrainz** or **Last.fm** as the preferred provider. MusicBrainz is the initial preference. Enable the desired providers and fallback to the other enabled provider for fields not yet verified.
2. MusicBrainz public noncommercial lookups are keyless. Enter a real administrator contact email or URL for the application's identifying User-Agent. Review the service's usage terms and rate limits. Test the connection after saving configuration.
3. For Last.fm, put the API key in the masked field. The shared secret is optional (not required for read-only track and artist lookups). Saving credentials through the admin UI requires an installation encryption secret: `METADATA_SETTINGS_KEY` (at least 24 characters), or the existing `SPOTIFY_SETTINGS_KEY` / Docker `SCANNER_SECRET`. On Cloudflare, add the installation key via Worker Settings → Variables and Secrets (secret type), or `npx wrangler secret put METADATA_SETTINGS_KEY`. Use a strong random value and preserve it through deploys; replacing or losing it prevents decryption. Docker Compose exposes the optional `METADATA_SETTINGS_KEY`, `LASTFM_API_KEY`, and `LASTFM_SHARED_SECRET` environment variables. Set them via secrets or your private stack configuration, never in Git. Cloudflare can use environment secrets `LASTFM_API_KEY` and `LASTFM_SHARED_SECRET` too. A saved credential overrides the runtime environment values. The backend uses AES-GCM to store admin-supplied credentials and never returns them to a client or peer.
4. Enable scheduled metadata enrichment (opt-in), save settings, test, and click **Run batch now** if desired. Five minutes is the default interval. Intervals are 5, 10, 15, 30, 60, and 120 minutes. Manual runs have a cooldown to avoid stampeding; the status reports the most recent bounded batch. Ordinary telemetry sharing remains independently controlled in Network → Crons.
5. Keep Last.fm redistribution off unless the administrator has the necessary permission. Enable **Trust verified metadata from administrator-connected peers** only for a registry whose administrators you trust. Approved user-added peers still supply listening telemetry; their field claims are not automatically trusted for the new verified cache. If Last.fm redistribution is permitted and enabled on both servers, eligible Last.fm genre fields can also be reused.

## Metadata architecture

The new `hive_metadata`, `hive_metadata_jobs`, `hive_metadata_cursors` tables are additive. Historical and newly imported plays are discovered in sequence order, in small pages; the local library is also discovered incrementally after the historical event backlog. Remote-only library tracks enter this verification queue when their listening events arrive. Jobs are keyed by artist and exact track/album identity (artist-only jobs collect country/tag facts). Each automatic or manual batch attempts at most one entity and at most one call per enabled metadata provider, not one call per listen or every song in a playlist. Failed fields are retried later; verified nonempty fields are reused, not replaced simply because provider preference changes. Initial enrichment takes many cycles; empty/ambiguous results remain unknown.

MusicBrainz supplies a recording's first-release year and its artist's associated country/area code, where an unambiguous exact search match exists. It can also supply tags. Artist area is a provider-reported association, not listener location or an independently verified birthplace. Last.fm supplies track/artist tags with identity checks; wiki publication timestamps are not release dates, and Last.fm does not reliably provide dedicated country/release-year fields. Fallback is useful for those fields. The cache records provider, reference URL, timestamp and whether verified on this host or reused from a trusted peer. Only a small subset of response data is retained; no full upstream payloads are cached. Last.fm fields have a conservative installation-level insertion budget (10,000 new fields; no claim of measuring all provider-specific bytes across an entire network). Site operators must comply with the actual API agreements, including attribution, caching, and commercial-use conditions.

MusicBrainz factual release-year and country fields can be exchanged via `/api/telemetry/metadata/feed` separately from the ordinary `/api/telemetry/feed`. The sharing endpoint sends a cursor-limited page of 20 locally verified fields with provenance, subject to existing library/telemetry sharing settings. MusicBrainz supplementary tags are not exported by this feed. Last.fm fields are not exported unless the administrator explicitly enables permitted redistribution. Trust is administrative, not cryptographic proof of an upstream response. The receiver checks a directly configured trusted administrator peer in rotation, skips fields already known and never re-exports peer-supplied facts as locally verified. Thus this version does not implement transitive proof/federation across arbitrary peers. Losing access to a peer is not a reason to erase a library or listening ledger. The new feed has its own cursor; historical enrichments do not replay listening events or change a play's UUID. Older WASP versions remain stream/catalogue compatible but cannot exchange this new provenance feed. Cloudflare cannot reach private Tailscale endpoints without a reachable route.

The existing telemetry summaries join the new cache to listening records, including peer and old historical events whose metadata was missing. Music by Decade includes segmented rows from Pre-1960 through the current decade, hover values and a highlighted top album where known. Unknown years are excluded and coverage remains visible. Origin heat map uses provider-reported country, not the location of the listener. Artwork first attempts the local endpoint; on failure the browser tries up to three registered, reachable peer image endpoints, prioritizing the origin when known and using Docker's same-origin `/_peer/<id>` relay when supplied. This is bounded browser fallback, not a persistent server-side artwork mirror. Offline peers and missing art can still produce a placeholder.

## Request queue resource optimization

`GET /api/admin/requests` now reads saved request availability snapshots (counts, missing songs and check time), rather than opening and parsing the entire local and peer library once per requested playlist. The database removes the redundant original Spotify track list from the queue response. Legacy requests with no snapshot initially say availability check pending. Use the existing Refresh button for a single request or allow the rotating scheduled matcher to update it. The queue can be stale; completion still checks availability and enforces v17.0.4 verified/unverified source rules before marking done. Individual refresh/completion and the bounded background matcher still use the stored catalogues and can be resource-intensive on exceptionally large libraries.

Matching uses temporary normalized-title maps rather than repeated whole-library searches for every song. Count-only checks avoid generating peer reference hashes unnecessarily. Periodic metadata enrichment, request reconciliation, private Spotify draft refresh, and peer catalogue refresh run in separate minute slots within each five-minute cycle. The automatic request matcher processes one pending request per cycle; drafts and catalogue refresh are similarly bounded. Uploads no longer rescan every requested playlist synchronously. Very large queues take longer to converge. This targets the observed Cloudflare HTTP 503 / 1102 queue-read path; real Worker CPU, memory, and D1 row-read budgets have not been measured, and this is not a guarantee that every operation fits Cloudflare Free limits.

## Tests and deployment

- `node --test tests/*.test.mjs` includes mock Last.fm and MusicBrainz identity matching, encrypted credential storage, historical aggregation, trusted peer reuse and sharing controls, cache-backed request queue and completion verification.
- `python tests/ui_v17_0_5_metadata.py` checks the new admin subtab with mocked endpoints; `python tests/ui_v17_0_5_peer_art.py` verifies fallback URL selection in the sandbox (not actual peer image delivery); `python tests/ui_v17_0_1_charts.py` exercises the segmented chart and existing interactions; `python tests/ui_v17_playback_continuity.py`, `python tests/ui_v17_0_2_hive_controls.py` and `python tests/ui_v17_0_4_spotify_completion.py` cover regression behavior. Tests do not use real Last.fm keys, public providers, real Cloudflare D1/R2, Docker stacks, or actual production peers.
- Apply the changes-only patch to exactly v17.0.4, or use the full source archive. Back up persistent D1/R2/SQLite data, environment values, existing source, and Docker volumes first. Do not run destructive migrations or `docker compose down -v`. Deploy the test Worker first; confirm the admin version, load Requests, refresh one playlist and check completion. Then configure providers, confirm a small batch runs, and observe Worker CPU metrics and the telemetry coverage over multiple cycles. Preserve the old deployment for rollback; additive metadata tables may remain safely when rolling back code.
