# WASP v18.0.4 — HIVE Offline Metadata Engine

Staging upgrade from exact v18.0.3. No schema rebuild, audio edits or volume renames. The optional Docker feature indexes official MusicBrainz JSONL artist and release-group data in a separate SQLite file within the existing persistent local-state volume. Cloudflare continues using the existing HIVE metadata feed; it does not download the dataset. The Docker image adds Python 3 (standard library only); SQLite lookup uses Node 22's built-in SQLite module.

## Initial deployment and storage

1. Back up the existing WASP Docker state volume and R2/database as appropriate. Deploy the full source or overlay patch from v18.0.3. Rebuild the Docker image.
2. Check `df -h` on Docker storage. Recommend 15–20 GiB of **free** disk before downloading (including headroom for index updates); more may be needed depending on snapshot size. The installer refuses to begin with less than 10 GiB free, checks free space periodically and tries to preserve a 2 GiB reserve. This is a protective threshold, not a guarantee that the full dataset fits. Download and indexing sizes are not yet benchmarked with a full live snapshot.
3. Docker WASP → Admin → Network → Telemetry → HIVE Offline Metadata Engine → **Download / update MusicBrainz**. The first download is opt-in. Official JSON dumps are several GB; the browser may close while the job runs. Progress is per download / indexing phase, not a single guessed overall percentage. Cancel stops the background build without deleting the current installed index.
4. After the index is ready, click **Scan missing metadata** or resume the existing scanner. A completed continuous scan automatically detects new snapshot versions and new identities. Uncheck **Use configured online providers for unresolved metadata after offline matching** and save for offline-only factual enrichment while the index is installed. Disable the optional remote MP3 tag reads if focusing on the fastest offline factual pass; keep trusted peer metadata enabled if useful. For missing genres or unresolved tracks, re-enable fallback afterwards. An unavailable or not-yet-installed offline engine uses the existing provider workflow; you can disable the providers or pause the scan if desired.
5. Optional: set `WASP_OFFLINE_AUTO_UPDATE=1` in Portainer stack environment and redeploy to check for a newer official snapshot roughly weekly after an initial installation. Default is manual updates only. Manual download/update checks the current snapshot and skips a redundant download. An interrupted first download is retried from the start, not resumed byte-for-byte.
6. Cloudflare WASP → Admin → Network → Telemetry → trust administrator-connected peers, choose Docker as preferred, disable scheduled external provider enrichment if conserving resources, and pull metadata from HIVE. Docker must be reachable and metadata sharing enabled. Imported facts still require D1 reads/writes and the existing feed is paginated.

## Data source and matching

Official source: https://ftp.musicbrainz.org/pub/musicbrainz/data/json-dumps/ (LATEST, SHA256SUMS, artist.tar.xz and release-group.tar.xz only). See https://metabrainz.org/datasets/postgres-dumps and https://musicbrainz.org/doc/About/Data_License. Core facts from MusicBrainz are CC0. No audio, supplementary ratings/tags, biographies or artwork are indexed. Downloads use HTTPS and the published SHA-256 checksum manifest; GPG signature verification is not implemented.

The builder streams the compressed tar member (does not unpack arbitrary files), retains only matching keys, MBID, artist country and album first-release year, then builds search indexes. It validates the SQLite database before atomically replacing the previous index. The complete database is never transferred to Cloudflare. Data lives in `/app/.wrangler/state/hive-offline/index.sqlite`; database builds use separate temporary files, not the WASP database. A full update rebuilds the index, not the music library.

Exact normalized artist and album-credit/name matches are required. Multiple same-name identities, missing dates/countries, conflicting embedded years, and unknown artists/albums are left unresolved. Album dates refer to the release group (not necessarily the date of a particular recording, reissue or compilation track); existing embedded/verified facts are not overwritten by the offline pass. Offline matching currently handles artist and release-group identities, **not** individual recordings without known albums or genres. Unmatched metadata may use existing online providers when enabled. Current matching covers queued local-library identities and retained HIVE listening history; it does not pre-index every unplayed track from all remote peer catalogues.

Facts use the existing MusicBrainz reference representation and verified metadata feed. A separate snapshot/cursor keeps successful local metadata and avoids repeat lookups for unchanged identities. A new snapshot revisits unresolved jobs. Metadata caches are invalidated after factual matches so historical telemetry can be reclassified without replaying songs.

## Validation and limitations

Run `npm test`, `python3 tests/offline_index_test.py` and optional Chromium scripts. Full-size download and indexing, real Docker builds, Miniflare loopback networking and live Cloudflare deployments remain staging validation steps. No production state was touched. Do not delete Docker volumes to troubleshoot. If the service runs out of storage or is cancelled, the existing index remains installed; retry after resolving the problem.
