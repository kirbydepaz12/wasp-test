# WASP v18.0.1 — HIVE Request & Playlist Recovery (staging)

Upgrade baseline: v18.0.0. Back up the database, upload storage, configuration and Docker volumes. Do not delete inactive volumes. No change to the database bindings, mounted music folders, Caddy or existing routing and telemetry design. Schema changes are additive. This staging release was tested with Node/SQLite and Chromium fixtures, not deployed to a live service.

## Admin → Requests

Select one or more requests and choose Refresh selected, or use Refresh on an individual row. Individual songs are completed only when the normalized recording title and artist match the local or eligible connected peer catalogue; a live recording is not substituted for a studio recording. Artist and album requests show distinct local and peer catalogue counts and require an explicit Mark as done. Counts deduplicate within each group; the same recording can appear in both counts. Completed items appear in Previous requests. Playlist requests retain the matching/missing-song progress display and stay active if incomplete. A mirrored request's local completion is not a cancellation or completion of the authoritative request on its origin. The origin may complete its own request when it observes a match. No cross-peer privileged write endpoint was added.

## Origin tracking and housekeeping

The request feed identity must match a directly connected, authorized peer to identify its domain. Only administrators see the request-specific origin domain and can use Locate origin. A relayed request without a direct verified origin displays an unknown origin rather than falsely treating a relay as the origin. Network failures and server errors can mark an origin offline; disabled sharing, unverified identity and ambiguous HTTP responses are not treated as verified outages. An offline request shows Requestee is offline. Remove until online (also used for offline selected requests) hides it on this instance until a successful synchronization with that origin. It returns only if still active. Removal never affects audio or other peers. Ordinary v18 Remove / Remove all HIVE requests / Remove all requests retain their permanent local-dismissal semantics for remote requests, including offline requests in bulk clears; confirmation warns accordingly. Local cancellation remains federated. A remote-origin request is kept while incomplete unless the admin chooses to remove it.

## Playlist recovery and Spotify import

Private Spotify playlist imports support up to 1,500 known entries; previously an internal 100-entry cap truncated the available list. Spotify's public embed may expose fewer tracks than the actual playlist. The import displays matched, known missing, and (where a total is reported) titles not retrieved separately. Only known missing titles can be displayed. To supplement inaccessible Spotify titles, paste two tab-separated columns (title and artist) from a list you can access. Supplemental titles are user-supplied, not Spotify-verified. Spotify access is not bypassed.

Open Show songs not found in HIVE for per-song Search song and Request; search refreshes eligible peer snapshots in groups of four, up to 100 configured/approved candidates, and reports checked and responding peers. Catalogue matches do not guarantee that audio can be streamed. Automatic matching refresh uses bounded rotating peer subsets and cached catalogues. Unreachable peers may have stale or unavailable metadata. To finalize an incomplete private import, confirm Mark as done ANYWAYS; unmatched titles remain in the recovery list and Refresh matches can add them later. Existing deliberate track removals are preserved after partial finalization. An incomplete public admin playlist request is not forcibly completed by this private-owner action. Missing-song automatic request creation is bounded (up to four per draft run, ten per import owner per day, global active queue ceiling 500); individual Request buttons remain available subject to the same quota.

Previously unavailable playlist references display saved song, artist and album metadata when available. Search song searches eligible connected peer catalogues in batches, allows the owner to explicitly use a matching alternative, and changes only that playlist reference. If the old reference has no saved title/artist, enter them manually. Request registers the known song with normal request controls. No audio is deleted or moved. If a peer is temporarily offline or unreachable, search can only use available/cached metadata; playback itself is not verified by search.

## Validation and rollout

Run `npm test`, `python tests/ui_v18_0_1_refinements.py` and `python tests/ui_v18_features.py` (Chromium and Python Playwright required). Use the full ZIP for a clean source checkout or the changed-files ZIP only on exact v18.0.0. Stage Docker and Cloudflare separately; verify admin sidebar version `v18.0.1 · HIVE Request & Playlist Recovery`, confirm the database and volumes are retained, then check a long Spotify import, origin reconnect, and actual playback on the target network. Do not assume fixture tests verify Spotify service access, real D1 quotas or Docker build success. The v18.0.0 workerd Dockerfile fix is retained; allow adequate disk space for image rebuilds. No production deployment, credentials, or live request data included.
