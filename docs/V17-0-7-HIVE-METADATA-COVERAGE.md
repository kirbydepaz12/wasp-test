# WASP v17.0.7 — HIVE Metadata Coverage Enhancement

Staging release from exactly v17.0.6. This update improves historical listening metadata and adds the requested coverage monitor at **Admin → Network → Telemetry**. It does not change music playback, network routing, user data, or music requests. Smart routing remains reserved for v18.

## Coverage monitor

The monitor shows all retained local and imported HIVE listening events, not just the current public dashboard period. It uses the same release-year and country precedence as the public charts. Release-year coverage counts each play once; country coverage counts each play once. The percentages can differ from a filtered public dashboard. An empty ledger shows a dash rather than claiming full coverage. Counts are cached for up to five minutes and invalidated after successful metadata batches. If the coverage query fails, the settings remain accessible and the panel displays an unavailable state.

The **Scan missing metadata** button runs one bounded manual batch using saved settings. Its result is displayed below the button. For unattended scanning, enable scheduled metadata enrichment (five minutes by default). Save settings before scanning; manual runs respect the scheduler's cooldown/lease. The prioritized setting ranks jobs by the number of discovered listening events and favors artist/album jobs on ties. The counts reflect discovered portions of retained history; the scheduler walks the ledger in 30-event chunks, so priorities improve as history is discovered. This does not replay any listening events. Enrichment continues through the local track index after the history cursor reaches its end.

## Provider behavior

- Keep Last.fm and MusicBrainz settings from v17.0.6. Last.fm is used for tags; it does not provide reliable album release-year or artist-origin fields. Set a valid MusicBrainz contact email or HTTP(S) URL, enable MusicBrainz, and allow fallback when Last.fm is preferred.
- MusicBrainz first-release-date for a matching release group is saved once per normalized artist and album. It takes precedence over recording-level date, then recorded event/embedded track metadata. This lets matching songs on the same album reuse one lookup. A named album is not assigned a new recording-first-release-year simply because a release-group lookup fails. Older recording-level fields remain as fallback. An unknown album can still use recording-level metadata.
- Artist geography comes from MusicBrainz's begin-area country code where present, then its artist country/associated area. An associated country is a proxy for origin if more precise formation/birth data is not available. Wikidata is an optional enabled-by-default fallback within the existing fallback switch, using exact-name entity search and structured album publication date, country of origin, formation location or birthplace claims, not IP address or listener location. Only unique matching structured results with a single usable year/country are accepted. Wikidata also requires the saved valid administrator contact. Ambiguous names, guest credits, various-artists compilations, international groups, disputed dates, missing API records, unknown languages and unavailable provider responses may remain unclassified.
- Provider order still respects the saved preference and fallback switches. If Last.fm is the only enabled provider or fallback is disabled with Last.fm preferred, the factual fields will remain limited to information already available locally or from trusted peers. Last.fm-derived redistribution remains opt-in with permission; no credentials are exported.
- Trusted administrator-connected peers running this release can exchange verified album-level and Wikidata factual records over the existing metadata feed. Origin and listening-event cursors are preserved. Older WASP versions can keep exchanging normal telemetry but do not understand album-level records or Wikidata records. Imported peer metadata is not re-exported as locally verified. User-published peers are not implicitly trusted. The trusted-peer option is not cryptographic provider authentication.

## Bounded processing

A default batch checks one entity. Settings allow up to 3 entities for installations with headroom; when trusted peer imports are enabled, local work is capped at one entity per batch to reserve SQL budget. A batch stops starting new work after approximately 20 seconds, and each upstream fetch has an 8-second timeout. A maximum of 3 peer metadata records are imported per cycle, with cursor advancement restricted to processed entries. Discovery uses atomic bounded multi-row writes (at most 80 bind parameters per statement). Intra-batch calls to the same provider are spaced by at least 1.1 seconds; provider rate-limit responses defer the job and avoid additional calls to that provider in the same batch. This is not a global rate limiter across different servers or separately initiated tests. External lookups never execute on ordinary listener page loads. Only the cached coverage and an occasional SQL aggregate are used for monitoring. Actual Cloudflare CPU/rows-read usage depends on the real data and must be verified in staging; use 1 entity per batch on Free Workers.

## Deployment

1. Back up D1 or the Docker persistent state and the existing v17.0.6 source; apply the changes-only patch to exactly v17.0.6 or deploy the full source. Preserve all environment variables, secrets, mounts and peer settings.
2. Deploy the Cloudflare **test** Worker first or a staging Docker instance. Confirm v17.0.7 in the admin sidebar. The metadata schema migration adds `play_priority` to `hive_metadata_jobs` and uses new discovery/coverage cache keys. Existing telemetry, metadata, credentials and cursors are preserved. No destructive migration is performed.
3. Open Admin → Network → Telemetry. Confirm saved provider configuration, enable MusicBrainz and Wikidata fallback as appropriate, and test MusicBrainz. Enable scheduled enrichment and save. Choose **Scan missing metadata** to request a bounded batch. Check coverage over subsequent cycles, not just immediately after deploy. A provider miss or rate limit can cause no progress in a particular batch.
4. Verify public decade and artist-origin charts, and that audio continues when navigating between pages. Check Cloudflare invocation logs for CPU/memory/D1 errors. Do not reset telemetry or peer cursors.

Rollback: redeploy the previous full v17.0.6 source if needed; the new schema column and cache keys are additive. Do not roll back by deleting tables. v17.0.6 cannot use the new album-level cache correctly for charts; the event ledger stays intact.

## Tests

Local Node SQLite and mocked provider/browser tests cover album release group matching, history-wide reuse, popular music priority, coverage, migration, peer sharing, ambiguous results, Wikidata data handling, credential handling, and playback navigation. Provider responses and 2,252-play preview values are test fixtures. No live Last.fm/MusicBrainz/Wikidata key or actual Cloudflare/Docker deployment was tested. Real data completeness is not guaranteed.
